# Telegram Repost Bot

Копирует новые посты из чужого канала в ваш. Два независимых варианта:

* **`main.py`** — бот на aiogram 3.x. Ничего, кроме токена от @BotFather, не нужно.
  Публичный источник читается через веб-версию `t.me/s/<канал>`, приватный — если
  бота добавили туда админом.
* **`userbot.py`** — userbot на Telethon. Работает от вашего аккаунта, умеет
  вступать по ссылке-приглашению, но аккаунт рискует блокировкой.
* **`hybrid.py`** — userbot читает закрытый источник, а публикует бот: в вашем
  канале виден бот, а не личный аккаунт.

Начните с `main.py`: если источник публичный или вас пустят в него админом,
userbot не нужен.

## Два режима работы

| | 📡 Мгновенный (`live`) | 🌐 Опрос веб-версии (`web`) |
|---|---|---|
| Когда включается | бот — **админ** канала-источника | источник публичный, бота в нём нет |
| Как указать источник | **переслать боту любой пост** из канала | прислать ссылку `t.me/канал/123` |
| Приватные каналы | ✅ да | ❌ нет |
| Задержка | мгновенно | до `interval` секунд |
| Качество копии | идеальное: альбомы, кружки, гифки, опросы | текст, фото, видео, файлы |

Режим выбирается автоматически на шаге 1.

## Возможности

* пошаговая настройка через `/start` (пересланный пост или ссылка → ваш канал);
* проверка, что бот — админ целевого канала с правом `can_post_messages`;
* копирование текста с форматированием, фото, видео, альбомов, файлов, голосовых;
* нативный `copy_message`, если бот имеет доступ к каналу-источнику, иначе — пересборка поста;
* хранение `last_seen_id` в `state.json` — после перезапуска дублей не будет;
* обработка FloodWait, закрытых каналов, удалённых постов, потери прав.

## Команды

| Команда | Что делает |
|---|---|
| `/start` | Настройка: шаг 1 — пересланный пост или ссылка на источник, шаг 2 — ваш канал |
| `/stop` | Остановить репостинг (настройки сохраняются) |
| `/status` | Источник, цель, последний скопированный ID, интервал |
| `/set_interval <секунды>` | Изменить частоту проверки (от 15 сек) |

Управлять ботом может только владелец — тот, кто первым выполнил `/start`
(его ID сохраняется в `config.json` в поле `owner_id`).

## 1. Получаем токен у @BotFather

1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Введите имя бота и username (должен оканчиваться на `bot`).
3. Скопируйте токен вида `1234567890:AAH...` — это и есть `BOT_TOKEN`.
4. Рекомендуется `/setprivacy` → **Disable** не требуется: бот работает только в личке.

## 2. Добавляем бота админом в свой канал

1. Ваш канал → **Управление каналом** → **Администраторы** → **Добавить администратора**.
2. Найдите бота по username и добавьте.
3. Обязательно включите право **«Публикация сообщений»** (`can_post_messages`).
   Без него бот откажется запускаться и напишет об ошибке.

## 2.1. Приватный канал как источник

**Бот не может вступить в канал по ссылке-приглашению** (`t.me/+хеш`) — в Telegram
Bot API просто нет такого метода, это ограничение платформы, а не недоработка кода.
Добавить бота в канал может только его администратор, вручную.

Если источник приватный (ссылки вида `t.me/c/1916432895/17544`):

1. Откройте канал-источник → **Управление каналом** → **Администраторы**;
2. Добавьте бота администратором (достаточно права «Публикация сообщений»);
3. **Перешлите боту любой пост** из этого канала.

Бот сам определит канал по пересланному посту и включит мгновенный режим:
новые посты будут прилетать ему сразу, без опроса и без задержки.

Если вы не администратор канала-источника — приватный канал читать не получится
никак; нужен публичный канал.

> ⚠️ Если в канале-источнике включено «Ограничить сохранение контента»,
> переслать пост не выйдет — пришлите вместо этого ссылку `t.me/c/.../...`,
> она сработает так же, если бот уже добавлен админом.

Для **публичного** источника ничего добавлять не нужно — просто пришлите ссылку
на пост. Проверьте только, что `https://t.me/s/имя_канала` открывается в браузере
без входа в аккаунт.

## 3. Локальный запуск

```bash
pip install -r requirements.txt
export BOT_TOKEN="1234567890:AAH..."
python main.py
```

Затем в Telegram: `/start` → пришлите `https://t.me/somechannel/123` → пришлите `@ваш_канал`.

Копироваться будут посты **после** того, ссылку на который вы прислали.

## 4. Деплой на BotHost

1. Зарегистрируйтесь на [bothost.ru](https://bothost.ru) и создайте нового бота (Python 3.11+).
2. Загрузите в корень проекта файлы `main.py` и `requirements.txt`
   (через веб-панель «Файлы» или по FTP/SFTP).
3. В разделе **«Переменные окружения»** добавьте:

   | Ключ | Значение |
   |---|---|
   | `BOT_TOKEN` | токен от @BotFather |
   | `CHECK_INTERVAL` | (необязательно) интервал по умолчанию, сек |

4. В настройках запуска укажите стартовый файл `main.py`
   (команда запуска: `python main.py`).
5. Нажмите **«Установить зависимости»** — панель подтянет `requirements.txt`.
6. Запустите бота и откройте вкладку **«Логи»** — там появится
   `Бот запущен: @имя_бота`.

Файлы `config.json` и `state.json` создаются рядом с `main.py` автоматически.
Не удаляйте их при обновлении кода — иначе бот заново разошлёт старые посты.
На хостингах с эфемерной файловой системой переносите эти два файла между деплоями.

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | — | **обязательна**, токен от @BotFather |
| `CHECK_INTERVAL` | `60` | стартовый интервал опроса источника, сек |

## Файлы состояния

`config.json`:

```json
{
  "source_channel": "somechannel",
  "source_chat_id": -1001916432895,
  "source_title": "О,Челябинск!",
  "mode": "live",
  "target_channel": "@my_channel",
  "last_post_id": 1234,
  "interval": 60,
  "enabled": true,
  "owner_id": 111111111
}
```

`state.json`: `{"somechannel": 1234}` — последний увиденный пост по каждому источнику.

## Вариант 2: userbot на Telethon (`userbot.py`)

Работает от имени **вашего аккаунта**, а не бота. Единственный способ репостить из
канала, куда вас не пустят администратором: аккаунт умеет вступать по ссылке-приглашению.

| | Бот (`main.py`) | Userbot (`userbot.py`) |
|---|---|---|
| Что нужно | только токен от @BotFather | `api_id`, `api_hash`, номер телефона, session-строка |
| Вступить по `t.me/+хеш` | ❌ невозможно в Bot API | ✅ да |
| Приватные источники | только если бот добавлен админом | ✅ любые, куда пустят аккаунт |
| Альбомы, кружки, гифки, опросы | в режиме `live` — да | ✅ всегда |
| Задержка | мгновенно (`live`) или до `interval` (`web`) | мгновенно |
| Риск | нет | **аккаунт могут ограничить или заблокировать** |

### Риски — прочитайте до запуска

Автоматизация пользовательского аккаунта нарушает Terms of Service Telegram.
Аккаунт могут ограничить в отправке сообщений или заблокировать целиком, без
предупреждения и без разбирательства. Практика, снижающая шанс:

* заведите **отдельный номер**, не используйте основной аккаунт;
* не ставьте `SEND_DELAY=0` — мгновенные реакции читаются как автоматика;
* не репостите в десятки каналов с одного аккаунта;
* `SESSION_STRING` — это **полный доступ к аккаунту без пароля и SMS**. Не кладите
  её в git, не показывайте в скриншотах. Утекла — Telegram → Настройки →
  Устройства → завершить сеанс.

### 1. Получаем api_id и api_hash

1. Откройте [my.telegram.org/apps](https://my.telegram.org/apps), войдите по номеру.
2. **API development tools** → заполните `App title` и `Short name` (любые).
3. Скопируйте `api_id` (число) и `api_hash` (строка).

### 2. Логинимся и получаем SESSION_STRING

Делается **один раз и на своём компьютере** — нужен ввод кода из Telegram,
на хостинге терминала для этого нет.

```bash
pip install -r requirements-userbot.txt
export API_ID=1234567
export API_HASH=abcdef0123456789abcdef0123456789
python userbot.py --login
```

Введите номер телефона, код из Telegram и (если включена) 2FA-пароль.
Скрипт напечатает длинную `SESSION_STRING` — скопируйте её.

### 3. Запуск

```bash
export API_ID=1234567
export API_HASH=abcdef0123456789abcdef0123456789
export SESSION_STRING="1BQANOTEuMTA4LjU2..."
export SOURCE="https://t.me/+YZshvpW4VGgzZWQy"   # или @channel, или -100...
export TARGET="@my_channel"
export SEND_DELAY=2
python userbot.py
```

На BotHost те же пять переменных задаются в разделе «Переменные окружения»,
стартовый файл — `userbot.py`, зависимости — из `requirements-userbot.txt`.

### Что умеет `userbot.py`

| Функция | Назначение |
|---|---|
| `resolve_source` | вступает по `t.me/+хеш` (`ImportChatInviteRequest`), подписывается на публичный канал (`JoinChannelRequest`), понимает `t.me/c/<id>/<post>` и `-100...` |
| `events.Album` | альбом приходит одним событием и уходит одним сообщением, не рассыпаясь |
| `events.NewMessage` | одиночные посты; части альбомов пропускаются, чтобы не было дублей |
| `copy_messages` | копия **без** пометки «Переслано из». Нужна пометка — замените тело на `client.forward_messages(target, messages)` |
| `catch_up` | после рестарта досылает до 50 постов, вышедших пока скрипт не работал |
| `userbot_state.json` | последний скопированный ID |
| обработка `FloodWaitError` | ждёт ровно столько, сколько просит Telegram, и повторяет |

## Вариант 3: гибрид (`hybrid.py`)

Userbot **читает** приватный источник, а публикует в ваш канал **бот**.
Смысл: вступить в закрытый канал может только аккаунт, но в целевом канале
подписчики видят бота, а не ваш личный профиль — удобно, когда канал ведёт команда.

```
приватный источник → Telethon (ваш аккаунт, только чтение)
                   → скачивание медиа в память
                   → Bot API sendPhoto / sendVideo / sendMediaGroup
                   → ваш канал (от имени бота)
```

Требуется всё сразу: токен бота **и** доступ к аккаунту.

```bash
pip install -r requirements-hybrid.txt

export BOT_TOKEN="1234567890:AAH..."          # публикует
export API_ID=1234567                          # читает
export API_HASH=abcdef0123456789abcdef0123456789
export SESSION_STRING="1BQANOTEuMTA4LjU2..."   # из `python userbot.py --login`
export SOURCE="https://t.me/+YZshvpW4VGgzZWQy"
export TARGET="@my_channel"
export SEND_DELAY=2
python hybrid.py
```

`hybrid.py` переиспользует `resolve_source` из `userbot.py` — держите оба файла рядом.

При старте бот сам проверяет, что он админ целевого канала с правом
«Публикация сообщений», и пишет понятную ошибку, если нет.

### Что учтено в `hybrid.py`

| Задача | Решение |
|---|---|
| Разметка | свой конвертер `entities_to_html`: offset'ы Telegram считаются в UTF-16, поэтому эмодзи и символы вне BMP не сдвигают теги |
| Спойлеры | штатный `html.unparse` из Telethon их **молча теряет** — конвертер выдаёт `<tg-spoiler>` |
| Премиум-эмодзи | `<tg-emoji>` Bot API у обычных ботов отклоняет — тег снимается, текст остаётся |
| Альбомы | один `sendMediaGroup` с `attach://`, подписи выровнены по файлам; если не ушёл — части отправляются по одной |
| Длинная подпись | больше 1024 символов — медиа с обрезанной подписью, полный текст отдельным сообщением |
| Стикеры и кружки | у них нет подписи — текст уходит следующим сообщением |
| Файл больше 45 МБ | медиа пропускается (лимит Bot API), текст поста не теряется |
| FloodWait | ответ `429` с `retry_after` — ждёт ровно столько и повторяет |
| Рестарт | `hybrid_state.json`, `catch_up` досылает до 50 пропущенных постов |

## Какой вариант выбрать

| Ситуация | Файл |
|---|---|
| Источник публичный | `main.py` |
| Вас добавят админом в источник | `main.py` (режим `live`) |
| Источник закрыт, нужен вход по ссылке-приглашению | `userbot.py` |
| То же, но в вашем канале должен публиковать бот | `hybrid.py` |

## Ограничения

* бот не может вступить в канал по ссылке `t.me/+хеш` — его добавляет админ вручную
  (ограничение Bot API);
* приватный источник работает, только если бот в нём администратор;
* в режиме `web` веб-версия отдаёт только последние ~20 постов — при простое дольше
  интервала очень старые посты будут пропущены;
* файлы больше 45 МБ не перезаливаются (лимит Bot API);
* за один цикл отправляется не более 10 постов с паузой 3 сек — защита от FloodWait.
